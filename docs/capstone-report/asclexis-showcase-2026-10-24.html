Patient drags a lab result PDF, a photo of a printout, or an HL7 FHIR export into the upload view. Uploaded files are stored AES-GCM encrypted with this profile's key. The upload goes to the backend on 127.0.0.1.

03 Local LLM & Model Selection

Local inference runs through one facade (ModelRunner) over two local providers. An opt-in cloud runner sits outside it as a documented exception. All inference is local by default.

LlamaCppProvider
default · local GGUF
OllamaProvider
localhost-only by design
External runner
opt-in · off by default · outside ModelRunner

LlamaCppProvider

llama-cpp-python, lazily imported so the app boots without a model present. Model files come from an explicit download step (src/backend/scripts/download_models.py, Hugging Face or ollama pull). The default assistant path needs no model.

  • core/llm/llama_cpp_provider.py
  • no-LLM fallback stays functional

OllamaProvider

Optional provider for users who already run Ollama. The provider refuses any non-local URL when it is constructed; tested.

  • core/llm/ollama_provider.py
  • default 127.0.0.1:11434

External runner

An opt-in cloud runner sits outside the ModelRunner facade as a documented exception. It is off by default and redacts by default. Redaction is pattern-based. Two callers can reach it: the assistant and interpretations.

  • core/external_runner.py
  • modules/redaction.py — strict by default
  • per-profile opt-in, off by default
  • callers: api/assistant.py:867, api/interpretations.py:522

Citation checks

  • [YOUR_RESULTS:N] labels the patient's own values in the legacy prompt. It is a context label; the validated marker is [cite:N].
  • [REFERENCE:N] labels knowledge-base entries (src/backend/scripts/seed_knowledge_base.py).
  • Memory & session history are labeled non-citable
  • Agent path: the guard drops any sentence it cannot map to a source. Legacy path: validate_response checks [cite:N] markers.

Constitutional limits

  • Education only — a prohibited-pattern suite blocks diagnosis and dosing language (tested; no test can prove "never").
  • interpret_safety prohibited-pattern suite must keep passing
  • Agent path abstains when it cannot ground an answer. The legacy path replaces a failed validation with the same abstention template (W-4).
  • 74 golden cases run in CI (agent path only). Whether the check is merge-required is not recorded in the repo.

Scored on 6 axes

  • groundedness, citation accuracy, abstention correctness, injection resistance = 1.0; advice leakage, PHI leakage = 0
  • consistency_score is a fixed 1.0 placeholder. An NLI replacement (HC-M11) is approved only behind a default-off flag; changing production scoring is owner-gated.
  • CI job agent-evals runs scripts/agent_eval_gate.py with absolute bars

05 Vault Architecture & The Right To Be Forgotten

One unencrypted master DB (profile names, password hashes, audit rows, knowledge base) + one vault per profile, SQLCipher-encrypted where SQLCipher is installed. Deletion is an ordered crypto-erase, not a row flag.

master.db unencrypted · names, hashes, audit rows
  • Profile metadata & auth (bcrypt, JWT HS256, token revocation)
  • Audit log for document and observation routes and 9 of 13 profile routes. Deleting a profile purges its audit rows.
  • Knowledge base ([REFERENCE] corpus)
  • Backup schedules
vault.db × N profiles SQLCipher where installed · sealed key
  • Observations, chat sessions/turns, feedback, care tasks, pinboards
  • DEK sealed per profile + a second copy sealed by one-time recovery code (SEC-RECOV-001)
  • Documents at rest: AES-GCM encrypted files
  • Access only via ProfileDbSession — never the master session
Backup archive unredacted by design
  • Backup archive: vault + sealed keys + plaintext master copy of this profile (by design, unredacted)

Crypto-erase — DELETE /profiles/{id} with phrase DELETE MY HEALTH DATA

1 · commit point
1 · Unlink the sealed key files first
2
Vault sweep — vault.db + encrypted documents
3
Backup sweep — this profile's backup sets
4
Master txn — purge audit rows, write anonymized tombstone

Backup ↔ restore

  • Deliberately unredacted — a redacted backup can't be restored
  • Profile-scoped restore: vault + sealed keys verbatim, only this profile's master row re-applied. The archive also carries a plaintext master copy of this profile's row and audit rows.
  • Gated on password + phrase RESTORE MY DATA
  • A lifespan scheduler runs due backups and records skipped_locked when a vault is closed (code path; not run in the audit).

Recovery codes

  • Profile creation issues a one-time recovery code sealing a second copy of the same DEK
