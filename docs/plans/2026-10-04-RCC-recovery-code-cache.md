**Goal:** After the settings-page recovery-code mutation settles, the TanStack mutation cache holds neither the password nor the issued recovery code.

**Architecture:** `useIssueRecoveryCode` gets `gcTime: 0`, and `RecoveryCodeCard` calls the mutation's `reset()` once it settles. ## Defect (measured at `origin/main` `90c502a`)

| Where | What |
|---|---|
| `src/frontend/src/components/settings/RecoveryCodeCard.tsx:48-52` | `issueRecoveryCode.mutate({ profileId, password }, …)`. TanStack stores the variables `{profileId, password}` and the response `{recovery_code, …}` on a `Mutation` in the client's `MutationCache`. |
| `src/frontend/src/services/profiles.ts:264-274` | `useIssueRecoveryCode` sets no `gcTime`; `App.tsx:71-78` sets no mutation defaults, so the default `gcTime` is 5 minutes (`query-core/src/removable.ts`, `updateGcTime`). |
| `RecoveryCodeCard.tsx:10-13` | The component comment says the code is "never written to the query cache". False today. |

How the cache lets go of a mutation (read in `node_modules/@tanstack/query-core/src`, 5.90.14):

1. `Mutation.optionalRemove()` removes the mutation only when it has **no observers** and is not pending.
2. While `RecoveryCodeCard` is mounted, its `MutationObserver` stays attached to the last mutation, so `gcTime: 0` **alone** keeps the password in the cache for as long as Settings is open.
3. `MutationObserver.reset()` detaches the observer and calls `scheduleGc()` with the mutation's `gcTime`. `reset()` **alone** therefore leaves the entry for the default 5 minutes.
4. Together: `reset()` detaches, `gcTime: 0` schedules removal on a 0 ms timer.

So the gate's two remedies are applied together. `gcTime` is a `useMutation` option and `useMutation` is called in `services/profiles.ts`, so that file gets a one-line change. It is not an ask-first file (the program row marks this item "ask-first: no"); the gate names the remedy, and this plan records the file it has to live in. L1 flags this in the PR body.

Replace the existing `renderCard` (`:40-49`):

```tsx
function renderCard() {
  const queryClient = new QueryClient({
    defaultOptions: { queries: { retry: false }, mutations: { retry: false } },
  });
  const utils = render(
    <QueryClientProvider client={queryClient}>
      <RecoveryCodeCard />
    </QueryClientProvider>
  );
  return { ...utils, queryClient };
}

/**
 * How many mutations in this client's cache still carry `needle` in their
 * variables or their result. The recovery code seals a second copy of the
 * DEK; the password unlocks the first. Neither may outlive the request.
 */
function cachedMutationsContaining(queryClient: QueryClient, needle: string): number {
  return queryClient
    .getMutationCache()
    .getAll()
    .filter((m) =>
      JSON.stringify({ v: m.state.variables, d: m.state.data }).includes(needle)
    ).length;
}

/**
 * Positive control: records whether the cache ever held `needle`. Without it,
 * a "nothing cached" assertion would also pass if the mutation never reached
 * this client at all.
 */
function watchCacheFor(queryClient: QueryClient, needle: string) {
  const seen = { value: false };
  const unsubscribe = queryClient.getMutationCache().subscribe((event) => {
    const m = event.mutation;
    if (m && JSON.stringify({ v: m.state.variables, d: m.state.data }).includes(needle)) {
      seen.value = true;
    }
  });
  return { seen, unsubscribe };
}
```

Existing tests call `renderCard()` and ignore the return value; they need no change.
