# HC-M21 Search & Filtering Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add local, encrypted cross-record search over documents, extracted entities, and observations with provider, date, category, and highlight filters.

**Architecture:** `modules/search.py` owns two rebuildable runtime tables in each profile database: a canonical derived row table used by the LIKE fallback and an FTS5 virtual table used when supported. The API refreshes the derived index before each bounded search, uses only `ProfileDbSession` for record data, and writes a fail-closed master audit event. The frontend follows TimelinePage and service conventions and wires the existing TopBar search field to the new route.

**Tech Stack:** Python 3.11+, FastAPI, SQLAlchemy asyncio, SQLite/SQLCipher FTS5, React, TypeScript, React Query, Vitest.
